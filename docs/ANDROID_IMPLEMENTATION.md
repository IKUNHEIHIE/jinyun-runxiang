# Android 重构实施与验收记录

## 目标与边界

以 https://mastergo.com/file/201619411459855?fileOpenFrom=project&page_id=M 为唯一视觉基线，交付完整用户客户端、必要后端与教师端适配、可安装且经过 Android 运行验证的 Debug APK。保留任务开始前已有的未提交修改。

## 已核实的现状

- 用户门户 `user-web`：Vue 3、TypeScript、Vite 5、Element Plus；旧界面主要为桌面布局。
- 管理后台 `admin-web`：Vue Pure Admin、Vue 3、Vite 7；独立运行。
- 服务端 `backend`：FastAPI、SQLAlchemy 2、MySQL，JWT + 数据库角色及 token_version 校验。
- `mobile-app`：Flutter 骨架，未包含 Android 工程，Flutter SDK 未在当前工具路径中。
- 现有业务：注册登录、课程章节与进度、测验、AI任务、社区审核评论、教师班级与作业批改、市集订单、研学打卡。
- 缺口：非遗百科实体与检索、签到、收藏与关注、完整个人资料、学生加入班级和提交作业等。
- Windows：Android Studio 位于 `D:/Android/Studio`，SDK 位于 `D:/Android/Sdk`，Android 36 平台，Java 25；可运行 Android 37 模拟器。
- WSL Ubuntu：Python 3.12、Node 22、Docker；既有 Dify 容器为其他资源，保持运行。新建隔离 Python 环境 `~/.venvs/jinyun-android`。
- 2026-10-16：现有 `backend/tests/test_security_regressions.py` 在 WSL 执行，24 项通过。

## 技术方案

在 `user-web` 内建立独立手机界面组件、设计变量与路由，复用已有业务 API，通过 Capacitor 8 创建原生 Android 工程。静态界面随 APK 打包，API 地址按环境注入，不依赖电脑上的前端开发服务器。保留旧界面源文件以便迁移复用。教师端独立于 Android 发布。

设计属性与完整分区保存在 `docs/mastergo/`，每个非空画板分别输出 JSON 与独立 HTML 基线。这些文件为设计证据，不代表功能页面已完成。空画板和独立导航图标须单独分类。原始 SVG 通过工具替换保存，不手绘近似图标。设计服务有限流，提取需重试。
